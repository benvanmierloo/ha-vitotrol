## Key File Locations

**Entry Points:**

- `custom_components/vitotrol/__init__.py`: Integration setup/teardown, wires API → coordinator → platforms
- `custom_components/vitotrol/config_flow.py`: Credential entry UI, scan interval options

- `custom_components/vitotrol/sensor.py`: Temperature, power, energy, duration sensors (read-only numerics and enums)

## Naming Conventions

**Files:**

- Lowercase with underscores: `sensor.py`, `config_flow.py`, `test_coordinator.py`
- Platform files: `{platform}.py` (sensor, binary_sensor, switch, number, select, climate)
- Test files: `test_{module}.py` (test_api.py, test_coordinator.py)
- Config/lists: `const.py`, `attributes.py`, `manifest.json`, `strings.json`

**Directories:**

- Lowercase: `custom_components`, `translations`, `brand`
- Integration name: `vitotrol` (matches DOMAIN constant)
- Test directory: `tests/` (no underscore, standard pytest convention)

**Classes:**

- PascalCase, prefixed with `Vitotrol`: `VitotrolEntity`, `VitotrolAPI`, `VitotrolCoordinator`, `VitotrolSensor`, etc.
- HA base class names at end: `VitotrolSensor(VitotrolEntity, SensorEntity)`, `VitotrolCoordinator(DataUpdateCoordinator)`
- Data classes: `VitotrolDevice`, `VitotrolAuthError`, `AttributeTypeInfo`, `AttrMeta`

**Functions:**

- snake_case: `entity_key_for_attr()`, `infer_unknown_metadata()`, `_strip_ns()`, `_xml_escape()`
- Public: Exported from module, no leading underscore
- Private: Leading underscore (`_send_request()`, `_xml_escape()`), not for external use
- Handlers: `async_setup_entry()`, `async_step_user()` (HA convention)

**Variables:**

- snake_case: `device_id`, `attr_id`, `raw_value`, `catalog`
- Constants: UPPERCASE (defined in `const.py`): `DOMAIN`, `DEFAULT_SCAN_INTERVAL`, `ATTR_INDOOR_TEMP`
- Private instance vars: Leading underscore: `_api`, `_device_id`, `_vitotrol_attr_id`
- Coordinator data keys: device_id (int), attr_id (int)

**Type Hints:**

- Used throughout: `async def login() -> None`, `def get_data(self, device: VitotrolDevice, attr_ids: list[int]) -> dict[int, str]`
- Type aliases: `type VitotrolData = dict[int, dict[int, str]]`, `type VitotrolConfigEntry = ConfigEntry[VitotrolRuntimeData]`

## Where to Add New Code

**New Feature (e.g., add humidity sensor):**
- Attribute definition: Add row to `_TABLE` in `attributes.py` (id, name, enabled, category)
- If enum: Add to `_ENUM_MAPS` dict
- If binary_sensor with custom on_values: Add to `_ON_VALUES` dict
- Register with platform: If known to be a sensor, it's auto-routed by category
- Tests: Add test cases in `tests/test_sensor.py` or relevant platform test

**New Platform (e.g., add cover for vent dampers):**
- Implementation file: Create `custom_components/vitotrol/cover.py` following the pattern in `sensor.py`
- Pattern to follow:
  1. Import base `VitotrolEntity`, coordinator, attributes, HA platform
  2. Define `async_setup_entry(hass, entry, async_add_entities)` that iterates devices and catalog
  3. Define platform entity class (`VitotrolCover(VitotrolEntity, CoverEntity)`)
  4. Implement `available`, `current_position`, `set_position()` using `_get_attr_value()` and `_update_coordinator_data()`
  5. Override `_polling_attr_ids()` if multi-attribute (like climate)
- Add platform to `PLATFORMS` list in `const.py`
- Add strings for UI in `strings.json`
- Add tests in `tests/test_cover.py`

**New Composite Entity (like climate reading multiple attributes):**
- Implementation: Add to `climate.py` (or new file if significant)
- Define configuration: Add to `CLIMATE_CONFIGS` or new list in `attributes.py`
- Register attrs: Override `_polling_attr_ids()` in entity to return set of all attr_ids needed
- Handle enum mapping: Use `info.enum_values` or `meta.enum_map` like climate does
- Tests: Cover preset/mode mapping, multi-attr polling, write operations

**Bug Fix or Refactor:**
- Identify layer(s) affected: api, coordinator, entity, platform, attributes
- Run tests: `pytest tests/` to ensure no regressions
- Follow existing conventions: Code style, naming, patterns
- Add tests if fixing bug with no test coverage: Create minimal `test_*.py` or add to existing

**Utilities / Helpers:**
- Shared helpers: `entity.py` (e.g., `entity_key_for_attr()`, `infer_unknown_metadata()`)
- API helpers: `api.py` module-level functions (e.g., `_xml_escape()`, `_find_text()`)
- Coordinator helpers: `coordinator.py` methods (e.g., `_get_attr_ids()`, `_do_update()`)
- Attribute helpers: `attributes.py` builders and registries

**Configuration/Dependency Changes:**
- SOAP endpoint: `const.py` (`API_ENDPOINT`, `API_NAMESPACE`)
- Polling defaults: `const.py` (`DEFAULT_SCAN_INTERVAL`, `REFRESH_INITIAL_WAIT`)
- Dependencies: `manifest.json` (`requirements` list)
- HA minimum version: `manifest.json` (`homeassistant` field)
- Supported platforms: `const.py` (`PLATFORMS` list)
